# Context transitions

Choose a transition when a phase finishes or the harness signals context pressure. Preserve the decisions and acceptance criteria the next phase needs in authoritative artifacts.

| Situation | Action |
| --- | --- |
| Current context is useful and sufficient | Continue |
| A self-contained ticket supersedes the previous implementation context | Start a fresh context using the harness's available controls |
| Work moves to another directory, harness, or collaborator | Write a handoff with source pointers and unresolved decisions |
| A substantial independent task can be delegated with authorization | Use a scoped subagent with the required artifacts |
| Context pressure requires compression | Use supported compaction, keeping current scope, decisions, evidence, and remaining work |

Context limits and controls depend on the harness and selected model; avoid a fixed token threshold or assuming slash commands exist. Automatic compaction can happen during work. A summary must preserve accepted decisions and point to their original artifacts so work can continue without restarting the interview.

A handoff is a portable index: reference existing specs, decisions, commits, and evidence instead of duplicating them. Keep the actual conversation as a primary source when available, but make the next task executable from its artifacts.
