# Domain documentation

Loom uses a single domain context. Read relevant entries in root `GLOSSARY.md` before naming domain concepts. Read the relevant sections of `DESIGN.md` before changing architecture, protocols, requirement progression, workspace ownership, or persistence; keep the shared design current with the change.

Read relevant `docs/adr/` records when that directory exists. Create an ADR only for a consequential trade-off whose rationale would otherwise be lost; link it from the relevant design section. Missing ADR files do not block ordinary work.

Requirement-scoped specifications and decisions live in the selected material source described by `workflow.md` and Loom's context. Keep terminology in the glossary, system behavior in the design, and requirement-specific acceptance criteria in their requirement files.
